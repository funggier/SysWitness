# SysWitness v0.1.0-preview.2 — Windows x64 Portable

SysWitness can now present retained process lifecycle, DNS and connection observations in one activity timeline. The API matches the Sysmon subject Process GUID and recorded computer exactly, preserves source event references, and labels the grouping as derived.

This release also includes the process and network monitoring changes added after preview.1: Sysmon/Security lifecycle projection, local WMI collection with snapshot fallback, and read-only network/DNS feeds.

## Download and run

- `SysWitness-0.1.0-preview.2-win-x64-portable.zip`
- Windows x64, bundled .NET 10 runtime; extract and open `Start-SysWitness.cmd`.
- SHA-256: `5DAA103E17C0B155E1AA2C3C67642C0AB8F708D9090DE208B119DCAF6062C117`
- Stop the application before moving the entire folder. Keep private `config/` and `data/` together and do not redistribute them.

## Activity API

```http
GET /api/v1/processes/{processGuid}/activity?computer={recordedComputer}&limit=100
X-SysWitness-Token: <private-client-token>
```

The client needs **both** `processes.read` and `network.read`. Existing client registries are not silently granted new permissions. Use `source.computer` from a typed process/network record as the exact host filter.

The timeline combines Sysmon 1, 5, 3 and 22. Items retain their original event ID, source provenance and occurrence/observation times, with a typed lifecycle, connection or DNS payload. Missing/invalid identity input returns 400; an unknown host/GUID returns an empty page. No raw XML is exposed.

See the [Activity guide](https://github.com/funggier/SysWitness/blob/v0.1.0-preview.2/docs/PROCESS_ACTIVITY_TH.md) for paging, permissions and limits.

## Limits and remaining work

- Activity correlation is verified with synthetic Sysmon fixtures. The development account cannot read Security/WMI event subscriptions and has no Sysmon channel. Live Sysmon end-to-end activity validation remains open.
- Relocation was verified between directory names on the same Windows computer. Other machines, volumes and filesystems remain unverified.
- Exact reported GUID/host equality is not independent verification of process identity. PID-only Security/WMI/snapshot records are excluded from this grouping.
- DNS and connection records in the same process do not prove causality or connection success. Collection gaps, retention and missing lifecycle events may leave an incomplete history.
- XML-based GUID query scanning still needs workload measurements and query-cost controls. Process tree/parent-child correlation, broader source identity matching, dashboard and MCP remain future work.
- This is an observation prototype with a localhost read-only API. It has no Windows control, blocking, quarantine or remote command capability.
