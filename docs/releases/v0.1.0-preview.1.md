# SysWitness v0.1.0-preview.1 — Windows x64 Portable Preview

**Purpose:** Windows host observation and read-only API only. This is a **prototype**, not a complete security monitoring solution or prevention tool.

## Download

- `SysWitness-0.1.0-preview.1-win-x64-portable.zip`
- Windows x64; bundled .NET 10 runtime and SQLite native dependencies.
- SHA-256: `338E11050A4D3980C00B6EEEDC4F8BC7DA55FC6013DF94D73758DA5278488439`
- No installer, no Windows service/driver, no registry changes or cloud dependency for the monitoring core.

## Quick start

1. Extract the ZIP to a writable local folder, for example `T:\Apps\SysWitness`.
2. Double-click `Start-SysWitness.cmd`; avoid running as Administrator unless a source requires it.
3. First run creates private `config/` with a locally generated owner token and `data/events.sqlite`. **Never share these files**.
4. Read `README-PORTABLE-TH.md` for API access, moving between locations, and scope limits.
5. Stop SysWitness before relocating the **entire** folder.

## Verified

- .NET Release build with zero warnings/errors.
- Self-contained ZIP extracted and launched without invoking installed dotnet.
- First-run token generated inside the portable folder, API/SQLite/Event Logs accessible.
- Application stopped, whole folder moved and renamed, restarted successfully.
- Previously stored event and token remained usable; collector checkpoint did not regress.
- Windows Event Log `System` and `Application` providers read successfully in this test; optional Sysmon is unavailable/degraded on the development machine.

The relocation test was performed on the same Windows computer across different folder names/paths. Other volumes, filesystems and computers have not yet been verified; source permissions, NTFS ACL behavior and Windows provider availability may differ.

## Important limitations

- Observation only; **no** firewall blocking, process termination, quarantine, prevention, remote shell or Windows control commands.
- API is loopback-only by default, authenticated, read-only and scoped. A future MCP adapter will use these same read-only permissions.
- Initial event log backfill is limited and collection is not provably lossless.
- The private `config/owner-token.txt` contains a readable secret. Keep the complete folder on a trusted storage volume and do not publish/sharing its runtime `config/` or `data/` folders.
- No GUI, no built-in MCP server, no advanced Sysmon semantic correlation yet.
